# AV Lane Change Simulator
## P0.2 Software Architecture v0.1

### Architecture flow

The frozen Phase 0 dependency concept is:

```text
Scenario
   ↓
Dynamics
   ↓
Simulation Engine
   ↓
Analysis
   ↓
SimulationResult
   ↓
Visualization / IO
```

Capability Evaluator is an independent Analysis component reserved for future theory integration.

GUI is an outer user-interface layer only.

### Core principles

The architecture must preserve:

```text
headless numerical core
one-way module dependencies
replaceable dynamics
theory/simulator decoupling
GUI/core decoupling
testability
reproducibility
batch execution support
```

### MATLAB namespace

Use package namespace:

```text
avlc
```

Example future calls:

```matlab
avlc.core.runSimulation(...)
avlc.analysis.computeGaps(...)
avlc.visualization.plotResults(...)
```

Do not add `+avlc` child package directories individually to the MATLAB path.

Only `src` should need to be added.

### Package layout

The intended package layout is:

```text
src/+avlc/
    +core/
    +model/
    +dynamics/
    +scenario/
        presets/
    +analysis/
    +result/
    +visualization/
    +io/
```

Top-level project areas include:

```text
app/
scenarios/
tests/
examples/
data/
docs/
```

### Model responsibility

`+model` owns fundamental software data models such as:

```text
VehicleState
Vehicle
Road
SimulationConfig
```

Phase 0 should avoid unnecessary deep inheritance hierarchies.

Prefer simple structures or lightweight value-like data models when appropriate.

### Scenario responsibility

Scenario answers:

```text
What does the simulated world look like?
```

It describes roads, vehicles, initial conditions and events.

It does not numerically integrate vehicle motion.

### Dynamics responsibility

Dynamics owns state propagation:

```text
(state, input, parameters, dt)
    ->
nextState
```

The Simulation Engine must not embed vehicle-specific motion equations.

### Core responsibility

The core simulation engine coordinates simulation execution.

Future primary entry point:

```matlab
result = avlc.core.runSimulation(scenario, config);
```

The engine must remain independent of GUI and visualization.

### Analysis responsibility

Analysis computes quantities derived from simulation state.

Early Phase 0 targets include:

```text
gaps
relative velocity
```

Future reserved theory interface:

```text
evaluateCapability
```

### Result responsibility

SimulationResult is the authoritative numerical output of a simulation.

Visualization and export should consume this result rather than recomputing dynamics.

### Visualization responsibility

Visualization is read-only with respect to numerical simulation history.

It may draw:

```text
road
vehicles
time histories
animation
```

but must not generate its own physical state trajectory.

### IO responsibility

IO handles loading and saving simulation results and later scenario data.

File operations should remain outside the simulation engine where possible.

### GUI responsibility

App Designer GUI is an outer orchestration layer.

The GUI may:

```text
select/create Scenario
create SimulationConfig
call runSimulation
call visualization
```

The GUI must not contain the authoritative vehicle dynamics equations.

### Event system

Scenario reserves a simple time-triggered event system for cases such as:

```text
FO braking
RT acceleration
piecewise acceleration input
```

A future basic event may contain:

```text
time
targetVehicle
type
value
```

Do not implement a complex event framework during early Phase 0.

### Error handling

Invalid core inputs should raise explicit MATLAB errors with identifiers.

Do not silently continue after invalid numerical input.

Examples later include:

```text
dt <= 0
endTime <= 0
vehicle length <= 0
missing EGO
duplicate role
NaN state
```

### Frozen architecture decisions

Frozen for Phase 0:

```text
MATLAB primary environment
two straight parallel lanes
EGO / FO / RO / RT roles
six-state software interface
vehicle geometric center reference
SI internal units
headless simulation core
GUI/core separation
SimulationResult-driven visualization
independent Capability Evaluator
avlc MATLAB namespace
```

### Provisional decisions

Not yet frozen:

```text
final ego dynamics
final lateral lane-change trajectory
numerical integration method
complete Event representation
Scenario persistence format
GUI layout
```

### Reserved concepts

Reserved but not implemented:

```text
K_T
K_O_abort
commitment boundary
capability margin
HJ / viability numerical methods
```
