## Public entry point and input boundary

```matlab
result = avlc.core.runSimulation(scenario, simulationConfig, egoControl);
```

This replaces the earlier two-argument placeholder. It is the only simulation
entry point. Scenario, SimulationConfig and Control validation are reused in
that order, without copying their structural rules or modifying the inputs.
`simulationConfig.dt` and `simulationConfig.endTime` retain their frozen names
and positive finite numeric scalar requirements (seconds). The configuration
validator still permits a nonintegral ratio; the engine adds its own grid rule.

Exactly one constant Ego Control is supported, applied over every interval
`[t_k,t_{k+1})`. Arrays, function handles, policies and schedules are not Control
objects and fail the existing Control validator. The engine never constructs
a control command from a VehicleState acceleration snapshot.

## Fixed grid

Grid arithmetic uses double representations of the validated time inputs:

```text
ratio = endTime / dt
N = round(ratio)
gridTolerance = max(1e-12, 32*eps(max(1,abs(ratio))))
```

Require finite ratio, `1 <= N < flintmax`, and
`abs(ratio-N) <= gridTolerance`. The tolerance combines an absolute floor and
a scale-dependent 32-ULP allowance. The upper representability guard ensures
that N and N+1 can be represented distinctly; it is not a memory guarantee.
The frozen configuration excludes zero duration, so no zero-step case is added.

Time is the column `(0:N).' * dt`, not repeated accumulation. The generated
times must be finite and satisfy
`abs(time(end)-endTime) <= gridTolerance*dt`. Thus the endpoint uses the same
documented ratio tolerance converted to seconds. The terminal time is never
overwritten to force decimal equality. No shortened final step, adjusted dt,
down-sampling or alternative integration policy is introduced.
Invalid or unrepresentable grids raise `AVLC:InvalidSimulationGrid` before
trajectory allocation. Ordinary allocation failures remain MATLAB errors.

## Synchronized propagation

| Authoritative role | Existing primitive called on each interval |
| --- | --- |
| EGO | `avlc.dynamics.stepEgoDoubleIntegrator` |
| FO | `avlc.dynamics.stepConstantVelocity` |
| RO | `avlc.dynamics.stepConstantVelocity` |
| RT | `avlc.dynamics.stepConstantVelocity` |

Each vehicle uses its own sample k to produce sample k+1 over the same dt.
No vehicle reads another vehicle's newly propagated sample. There is no
generalized factory or dispatcher, and no propagation equation or control-bound
inequality is copied into the engine. The P0.2.4 primitives remain authoritative.
Vehicle `dynamics.type="UNASSIGNED"` and `dynamics.parameters` remain untouched.

## Exact minimal SimulationResult schema

The result has exactly these top-level fields, with no analysis placeholders:

```text
result.time                       (N+1)-by-1 double, seconds
result.states.EGO                 (N+1)-by-1 VehicleState struct array
result.states.FO                  (N+1)-by-1 VehicleState struct array
result.states.RO                  (N+1)-by-1 VehicleState struct array
result.states.RT                  (N+1)-by-1 VehicleState struct array
result.controls.EGO               N-by-1 Control struct array
result.metadata.scenarioName      scenario.name
result.metadata.dt                simulationConfig.dt
result.metadata.endTime           simulationConfig.endTime
result.metadata.numSteps          N
result.metadata.controlMode       "CONSTANT_EGO_CONTROL" (string scalar)
```

`states` contains exactly four roles; `controls` contains EGO only. Metadata
contains exactly the five named fields. Supplied name and time metadata values
are retained as supplied; no timestamp, UUID, machine data or Git hash is added.

Histories are preallocated. Sample 1 is exactly the corresponding supplied
`scenario.vehicles.<role>.initialState`, including numeric types, additional
compatible fields and original acceleration snapshots. It is not reconstructed
or normalized. Later samples update the six dynamics-owned fields from the
primitive output, which is validated by its existing VehicleState creator.
To maintain homogeneous struct-array schemas, any compatible initial metadata
fields are carried unchanged at later samples and have no dynamics meaning.

`controls.EGO(k)` equals the supplied egoControl, including compatible metadata,
and describes state(k) -> state(k+1). There are N controls and N+1 states;
there is no fictitious terminal command and no FO/RO/RT command history.
After t=0, Ego acceleration snapshots record the applied constant control;
surrounding acceleration snapshots become zero. Initial snapshots never drive
the propagated trajectory (TSC-03).

## Feature limits and errors

| Condition | Public error |
| --- | --- |
| Invalid Scenario | `AVLC:InvalidScenario` |
| Invalid SimulationConfig | `AVLC:InvalidSimulationConfig` |
| Invalid Control | `AVLC:InvalidControl` |
| Nonintegral, zero-step or unrepresentable grid | `AVLC:InvalidSimulationGrid` |
| Capability evaluation enabled | `AVLC:UnsupportedSimulationFeature` |
| `storeEveryStep=false` | `AVLC:UnsupportedSimulationFeature` |
| Control outside frozen Ego bounds | `AVLC:ControlOutOfBounds`, from dynamics |

Other validator/dynamics failures propagate unchanged, including nonfinite
propagated-state errors. No errors are unnecessarily wrapped or controls clamped.
Structurally valid capability and storage flags remain valid configuration
data; the engine explicitly rejects unsupported requests instead of ignoring
them. Validation precedes feature rejection, which precedes grid construction.
The engine itself does not introduce a new timestep validator.

## Determinism, immutability and responsibility

Identical inputs produce identical results without randomness, wall-clock
time, parallel execution or external mutable state. Scenario, config and
control are unchanged; trajectories belong to the returned result.

Unsafe but structurally valid scenarios remain simulatable. There is no
vehicle-order, lane-occupancy, collision, minimum-gap or progressive `vy>=0`
check. Negative velocities and lateral zero crossings continue normally when
the supplied control is admissible. Surrounding vehicles retain general
constant-velocity kinematics, including unusual initial velocities.

P0.2.5 does not implement Theory State Builder, Safety Evaluator, Capability
Evaluator, reduced-state mappings, safety gaps, relative velocities, W/d/K
derivation, reserves, controller frameworks, time-varying commands, events,
visualization, animation, GUI, file persistence, Monte Carlo, parameter sweeps
or parallel simulation. `evaluateCapability` remains its explicit placeholder.
No P0.2.6 work is included.
