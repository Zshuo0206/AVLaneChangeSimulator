## API, input and responsibility

```matlab
cap = avlc.analysis.evaluateCapability(scenario, z)
```

The function first reuses `avlc.scenario.validateScenario`. Its local reduced
state validation requires a scalar struct with y,w,gR,cR,gF,cF,gT,cT, each a
finite real numeric scalar. Malformed z raises `AVLC:InvalidTheoryState`.
Compatible extra fields are accepted and ignored; no new public state model
is introduced. Numeric operands are evaluated as doubles without mutating
inputs. Existing Scenario validation errors remain unchanged.

The frozen pre-decision domain is **y >= 0 and w >= 0**; violation raises
`AVLC:CapabilityDomainViolation`. This restriction belongs to Parts I-III,
not the P0.2.6 builder, which continues to represent signed y and w.

The function consumes z directly. It never reconstructs z from initial or
current VehicleStates, advances a simulation, chooses controls or evaluates
a trajectory. The layering is physical states -> buildTheoryState -> z ->
evaluateCapability. Simulation Engine remains decoupled, including its
existing rejection of automatic capability evaluation.

## Constants and Road reference

```text
A = scenario.theoryParameters.maxLateralAccel
B = scenario.theoryParameters.maxLongitudinalBrake
C = scenario.theoryParameters.maxLongitudinalAccel
overshoot = scenario.theoryParameters.targetOvershoot
W = scenario.road.targetLaneCenterY - scenario.road.originalLaneCenterY
```

W equals targetLaneCenterY and laneWidth under the Phase 0 Road contract.
It is local only, with no duplicated Scenario or TheoryModelParameters field.
Vehicle acceleration snapshots and Scenario initial conditions do not enter
these calculations. Positions/gaps use m; speeds use m/s; times use s.

## Part I: abort

On the required initial closed corridor gR >= 0 and gF >= 0:

```text
cO = cR + cF                            (internal only)

TRsafe = Inf                           if cR <= 0 or cR^2 <= 2*C*gR
         (cR-sqrt(cR^2-2*C*gR))/C      otherwise

TFsafe = Inf                           if cF <= 0 or cF^2 <= 2*B*gF
         (cF-sqrt(cF^2-2*B*gF))/B      otherwise

TG = Inf                               if cO <= 0
     (gR+gF)/cO                        otherwise

HO = min(TRsafe, TFsafe, TG)
TOmin = (w+sqrt(2*w^2+4*A*y))/A
abort.feasible = (TOmin <= HO)
```

Discriminant equality belongs to the infinite opportunity branch. Time
equality and the closed total-gap boundary are admissible. With finite HO:

```text
YO = A*HO^2/4 - HO*w/2 - w^2/(4*A)
```

A negative finite YO is preserved: it describes an empty abort-capable slice
in the pre-decision domain. YO is NaN when HO is infinite.

If gR < 0 or gF < 0, abort.feasible is false and TRsafe, TFsafe, TG, HO, YO
are all NaN. TOmin is still derived from valid y,w. No square-root opportunity
formula is applied outside the branch's required initial safe corridor.
Completion is evaluated independently.

## Part II: completion

For gT >= 0:

```text
HT = Inf                               if cT <= 0 or cT^2 <= 2*C*gT
     (cT-sqrt(cT^2-2*C*gT))/C          otherwise
```

For gT < 0, HT is NaN and completion.feasible is false. Abort is still
evaluated independently. For every valid y,w:

```text
DT = W-y
D0 = w^2/(2*A)
Dphys = D0-overshoot

TTmin = (sqrt(2*w^2+4*A*DT)-w)/A      if DT >= D0
        (w+sqrt(2*w^2-4*A*DT))/A      if Dphys <= DT < D0
        Inf                           if DT < Dphys
```

DT = D0 belongs to the first branch. DT = Dphys is physically recoverable
and belongs to the second branch when below D0.

For an initially safe target branch the completion-time comparison is
implemented as:

```matlab
isfinite(TTmin) && TTmin <= HT
```

The finite-time guard resolves the task's literal `Inf <= Inf` ambiguity in
accordance with authoritative Master section 12 Case III (no admissible
stable completion outside physical recoverability) and section 17 (infinite
HT still requires DT >= Dphys). MATLAB's bare `Inf <= Inf` returns true and
would violate both statements. All finite-time closed comparisons remain
unchanged. On infinite HT, feasibility therefore reduces to physical
recoverability; no finite window is invented there.

Only when gT >= 0, HT is finite and HT >= w/A:

```text
Dplus  =  A*HT^2/4 + HT*w/2 - w^2/(4*A)
Dminus = -A*HT^2/4 + HT*w/2 + w^2/(4*A)
YTin   = W-Dplus
YTout  = W-max(Dphys,Dminus)
```

Here completion.feasible is equivalent to the closed interval
YTin <= y <= YTout. At HT = w/A the window is the single natural-stopping
point. For HT < w/A, the finite slice is empty and all four window quantities
are NaN. They are also NaN when HT is infinite or gT < 0.

## Part III: current coexistence and finite geometry

```text
joint.dualCapable = abort.feasible && completion.feasible
```

**dualCapable means current coexistence of two execution capabilities.**
**dualCapable does NOT mean positive-time preservation of both options.**
It does not assert simultaneous execution of both maneuvers.

finiteGeometryAvailable is true exactly when both initial branch safety sets
hold, HO and HT are finite, and HT >= w/A. This is software metadata that the
finite construction is defined, even if the resulting capability slice is
empty. On this branch:

```text
Yfwd = min(YO,YTout)
Gamma = YTout-YO
```

Otherwise Yfwd and Gamma are NaN. The primary capability booleans always come
from the separate execution-time tests. Tests check their equivalence to
YTin <= y <= Yfwd on defined finite slices, including closed endpoints and
empty slices. Geometry never replaces the primary capability definitions.

**Gamma is only a frozen forward-boundary geometry selector.** Positive
Gamma selects YO as the smaller boundary; negative Gamma selects YTout;
zero means the boundaries coincide. It does not determine dynamic
option-loss order.

## Exact output fields and construction order

```text
cap.abort
    TRsafe, TFsafe, TG, HO, TOmin, YO, feasible
cap.completion
    HT, DT, D0, Dphys, TTmin, Dplus, Dminus, YTin, YTout, feasible
cap.joint
    dualCapable, finiteGeometryAvailable, Yfwd, Gamma
```

The top-level order is abort, completion, joint. There are no additional
fields. Flags are logical scalars; other fields are doubles. cO, W, A/B/C
remain internal.

## Inf / NaN and numerical conventions

Inf denotes a theoretically infinite opportunity or impossible TTmin.
NaN denotes a quantity not defined on this branch, never an alternative
encoding of unlimited opportunity:

| Branch | NaN fields |
| --- | --- |
| gR < 0 or gF < 0 | TRsafe, TFsafe, TG, HO, YO |
| HO = Inf | YO |
| gT < 0 | HT, Dplus, Dminus, YTin, YTout |
| HT = Inf or HT < w/A | Dplus, Dminus, YTin, YTout |
| finite joint geometry unavailable | Yfwd, Gamma |

TOmin and lateral completion quantities are still computed on structurally
valid y,w when a longitudinal branch is initially unsafe. No tolerances,
branch shifts, clipping, absolute-gap replacement or frontier normalization
are used. Computation uses the stated double-precision algebraic formulas.
