# AV Lane Change Simulator
## P0.2.8 Reserve + Active-Branch Diagnostics Contract v0.1

Status: FROZEN / PASS, as confirmed by the current project baseline.

## Purpose, source and scope

This step reports signed distance to existing finite capability boundaries
and identifies their current opportunity/boundary mechanisms. It consumes
the [P0.2.7 result](p0.2.7_current_capability_contract_v0.1.md) without changing
its formulas, fields, capability booleans or Inf/NaN conventions.

The unique frozen source remains
`AV_lane_change_Self_Contained_Core_Proof_Master.md`, selected by the proof
archive index, SHA-256
`5db01432a1fc63dc966f8aa5dfb5428cb6758da44545db3fe0330896eb4043ab`.
Relevant sections are 12 (current minimum-time cases), 16 (upper regimes),
31-33 (finite abort mechanisms), 37 (reserves), and 55 (Front-Rear Active-Set
Shielding). Earlier GF notes are not independent sources for this contract.

## Minimal API and inputs

```matlab
cap = avlc.analysis.evaluateCapability(scenario, z);
diagnostics = avlc.analysis.evaluateCapabilityDiagnostics(z.y, cap);
```

The new public signature is:

```matlab
diagnostics = avlc.analysis.evaluateCapabilityDiagnostics(y, cap)
```

Only y and already computed capability quantities are needed. Scenario, w,
model parameters, physical vehicle states and SimulationResult are not
inputs. No capability, opportunity time or frontier is recomputed. The
diagnostic function does not call the capability evaluator or engine.

The caller supplies a P0.2.7 result evaluated at the same current state as y.
The thin function checks consumed scalar fields, not full mathematical
consistency or freshness of that result. It introduces no public state model
or capability class. Compatible extra fields are ignored. Inputs are not
modified.

Consumed fields are:

```text
cap.abort: TRsafe, TFsafe, TG, HO, YO
cap.completion: DT, D0, Dphys, Dminus, YTin, YTout
```

y must be a finite nonnegative real numeric scalar. Consumed fields must
be real numeric scalars; DT/D0/Dphys must be finite. Opportunity values may
carry their existing Inf/NaN sentinels. YO/Dminus/YTin/YTout must be finite
or NaN, never an infinite substitute frontier. Malformed consumed inputs
raise `AVLC:InvalidCapabilityDiagnosticsInput`. This local input check is
not a replacement validator for the frozen P0.2.7 contract.

## Exact output and construction order

```text
diagnostics.reserves
    rO, lT, rT
diagnostics.abort
    activeSetDefined, activeR, activeF, activeG
diagnostics.completion
    currentBranch, upperActiveSetDefined, upperActiveI, upperActiveII
```

Reserves are double scalars in m. Active-set availability and membership
flags are logical scalars. currentBranch is a string scalar with exactly
one of the three values below. No R/F/G string label is needed: independent
boolean flags are the machine-readable truth and retain all simultaneous
memberships.

## Reserve definitions and signs

From Master section 37:

| Theory | Software | Definition |
| --- | --- | --- |
| r_O | reserves.rO | cap.abort.YO - y |
| ell_T | reserves.lT | y - cap.completion.YTin |
| r_T | reserves.rT | cap.completion.YTout - y |

Positive rO is inside the finite abort upper boundary, zero is on it,
and negative is beyond it. Completion's finite window corresponds to both
lT >= 0 and rT >= 0. Negative reserves are meaningful diagnostics, including
an empty abort slice with negative YO; they are never clipped to zero.
Subtraction is evaluated as double arithmetic without rounding or tolerance.

Each reserve is evaluated independently. A finite completion window can
yield defined lT/rT even if YO is undefined, and conversely rO can be defined
when the finite completion window is undefined. The joint finite-geometry
flag is not used to suppress an individually defined reserve.

## Abort active set and ties

For finite HO, including HO = 0:

```text
activeSetDefined = true
activeR = (TRsafe == HO)
activeF = (TFsafe == HO)
activeG = (TG == HO)
```

R denotes the original rear opportunity, F the original front opportunity,
and G the total-gap opportunity. Each equality is evaluated independently;
there is no first-index tie break or tolerance band.

When HO is Inf or NaN there is no defined finite limiting mechanism:
activeSetDefined and all three membership flags are false. In particular,
three unlimited opportunities are not labeled as a finite triple boundary.
The original Inf/NaN opportunity values remain available in the unchanged cap.

Master section 55 proves that if the finite front and rear opportunity
values both equal H > 0, then TG < H. Thus positive finite F/R equality is
shielded by G; it is not an effective F/R co-minimum. Tests use a valid
P0.2.7 example with TRsafe = TFsafe = 1 and TG = 8/11, correctly selecting G.
Positive R/G and F/G co-minima are retained. At the closed zero-time boundary,
gR = gF = 0 and positive cR,cF give TRsafe = TFsafe = TG = 0; all three flags
are retained. No artificial positive finite F/R-only tie is invented.

These flags select the mechanism defining HO; they do not assert that the
current lateral state lies on YO. Reserve equality is a separate question.

## Current completion time branch

Master section 12 describes the following mutually exclusive current-state
minimum-time cases. They are distinct from Master section 16's upper regimes.

| Condition using existing cap quantities | currentBranch |
| --- | --- |
| DT >= D0 | NON_OVERSHOOT |
| Dphys <= DT < D0 | OVERSHOOT_RETURN |
| DT < Dphys | PHYSICALLY_UNRECOVERABLE |

DT = D0 belongs to the first case. DT = Dphys is recoverable, and belongs
to the second case when below D0. With zero overshoot, Dphys = D0, so equality
belongs to the first case. No epsilon shifts branch membership.

This classification remains available when the longitudinal target branch
is unsafe or has no finite opportunity window: its lateral quantities are
still defined by P0.2.7. It is not synonymous with completion.feasible.

## Finite completion upper mechanisms

From Master section 16:

```text
YTout = W - max(Dphys, Dminus)
```

upperActiveSetDefined is true when Dminus and YTout are finite. For a valid
P0.2.7 result, this is exactly the defined finite-window branch, independent
of abort availability or whether the current y is inside that window.

```text
upperActiveI  = upperActiveSetDefined && (Dminus >= Dphys)
upperActiveII = upperActiveSetDefined && (Dphys >= Dminus)
```

Regime I is finite-traffic-time-limited stabilization through Dminus.
Regime II is the physical overshoot limit through Dphys. At exact equality
both are active. When the finite window is undefined, availability and both
memberships are false.

The current TTmin case and the upper-bound mechanism must not be conflated.
A NON_OVERSHOOT current state can have a Regime-II upper boundary; an
OVERSHOOT_RETURN current state can have a Regime-I upper boundary. A current
physically unrecoverable state can still have a defined finite boundary and
negative reserve relative to it. Tests explicitly protect these distinctions.

## Inf / NaN inheritance

If YO is NaN, rO is NaN. If YTin/YTout are NaN, lT/rT are NaN. There is no
substitute boundary, extra physical frontier, sentinel zero, realmax or
infinite reserve introduced for an undefined finite quantity.

P0.2.7's genuine infinite opportunities remain Inf in cap. The diagnostic
function does not reinterpret unlimited opportunity as a finite active
mechanism. Flags plus their availability fields distinguish an unavailable
finite active set from a defined set's membership.

## Verification and consistency review

Focused tests use actual P0.2.7 results and hand-calculated reserves,
positive/zero/negative values, NaN inheritance, unique R/F/G cases, R/G and
F/G ties, Front-Rear shielding and the zero-time triple tie. Binary offsets
near ties and thresholds protect exact branch membership. Both finite upper
regimes and their equality are checked separately from current time cases.
Finite signed-reserve membership is checked against the unchanged capability
booleans, including empty slices. A short existing simulation connects the
physical sample, builder, evaluator and diagnostics without a new adapter.
All existing P0.2.7 tests remain unchanged.

Gamma continues to describe frozen forward geometry only.
