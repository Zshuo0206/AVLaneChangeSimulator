# AV Lane Change Simulator
## P0.2.6 Theory State Builder Contract v0.1

Status: **Frozen** for the P0.2.6 single-state mapping.

This contract implements the mapping frozen by the
[Theory-to-Software Contract](p0.2.2b_theory_to_software_contract_v0.1.md).
It preserves the existing [data-model](p0.2.2_data_model_contract_v0.1.md),
[Scenario](p0.2.3_scenario_contract_v0.1.md),
[dynamics](p0.2.4_dynamics_contract_v0.1.md) and
[simulation-engine](p0.2.5_simulation_engine_contract_v0.1.md) contracts.

Theory State Builder performs a coordinate/model transformation.
It does not determine safety or capability.
Continuous analytical theory remains authoritative; this function only maps
software state into its variables.

## Public API and validation

```matlab
z = avlc.analysis.buildTheoryState(scenario, egoState, foState, roState, rtState)
```

Scenario supplies authoritative role-bound geometry and theory parameters.
The four VehicleState arguments supply the **current** physical states and
need not equal `scenario.vehicles.*.initialState`. Argument order assigns
roles EGO, FO, RO, RT. Positions never determine identity or reorder inputs.

The function first calls `avlc.scenario.validateScenario`, then
`avlc.model.validateVehicleState` on each supplied current state in argument
order. Existing error behavior is preserved: invalid Scenario raises
`AVLC:InvalidScenario` (including its existing nested causes); an invalid
current state raises `AVLC:InvalidVehicleState`. All six state fields must
remain structurally valid, including quantities ignored by the mapping.
Compatible extra fields remain subject to the existing validators and do
not become new theory inputs. No input is mutated.

## Exact reduced-state schema

The output is a scalar struct containing exactly these fields in this order:

```text
y, w, gR, cR, gF, cF, gT, cT
```

This is the frozen eight-dimensional state
`z = (y,w,g_R,c_R,g_F,c_F,g_T,c_T)`. No W, A, B, C, K, dF/dR/dT, cO,
capability flags or reserves are added. Positions and gaps use meters;
velocities and closing speeds use meters per second. Physical positions
refer to vehicle geometric centers under the existing SI convention.

| Reduced field | Physical-to-theoretical mapping |
| --- | --- |
| `y` | `egoState.y` |
| `w` | `egoState.vy` |
| `gR` | `egoState.x - roState.x - dR` |
| `cR` | `roState.vx - egoState.vx` |
| `gF` | `foState.x - egoState.x - dF` |
| `cF` | `egoState.vx - foState.vx` |
| `gT` | `egoState.x - rtState.x - dT` |
| `cT` | `rtState.vx - egoState.vx` |

Positive c means the corresponding longitudinal gap is closing:
Ego faster than FO gives positive cF, RO faster than Ego gives positive cR,
and RT faster than Ego gives positive cT. Equal velocities give zero;
reversing each comparison gives a negative closing speed.

## TSC-01: center-coordinate safety-distance mapping

Vehicle lengths use the existing authoritative
`scenario.vehicles.<ROLE>.geometry.length` field. The task's shorthand
`vehicle.length` does not introduce a second length field or change the
frozen Vehicle schema.

```text
LE  = scenario.vehicles.EGO.geometry.length
LFO = scenario.vehicles.FO.geometry.length
LRO = scenario.vehicles.RO.geometry.length
LRT = scenario.vehicles.RT.geometry.length

deltaF = scenario.theoryParameters.frontSafetyClearance
deltaR = scenario.theoryParameters.rearOriginalSafetyClearance
deltaT = scenario.theoryParameters.rearTargetSafetyClearance

dF = (LE + LFO)/2 + deltaF
dR = (LE + LRO)/2 + deltaR
dT = (LE + LRT)/2 + deltaT
```

The frozen formulas are unchanged: each gap subtracts the corresponding
geometric half-length sum and its required bumper safety clearance exactly
once. dF/dR/dT are local intermediates only; they are never persisted to
Scenario, TheoryModelParameters, VehicleState or z.

Positive g means margin remains relative to the longitudinal threshold;
zero g is the closed boundary; negative g lies below that threshold.
All three values are returned normally. Their interpretation does not
constitute a safety verdict by this builder.

## TSC-02: Road-derived lateral reference

```text
W = scenario.road.targetLaneCenterY - scenario.road.originalLaneCenterY
```

Under the current Phase 0 Road contract the original reference is zero,
so W equals `scenario.road.targetLaneCenterY` and `scenario.road.laneWidth`.
Road remains authoritative. W is a model/reference quantity, absent from z;
no W field is duplicated in Scenario or TheoryModelParameters and no W
helper is introduced in P0.2.6. The existing Road validation is unchanged.

## TSC-03 and ignored quantities

Every current state's ax/ay remains an acceleration snapshot and has no
effect on any reduced-state component. In particular, w is Ego **vy**,
never Ego ay. Surrounding FO/RO/RT y/vy also have no effect on z.
Unusual finite values in these fields are accepted through the existing
structural validators; missing, nonfinite or otherwise invalid values are
still rejected. No acceleration control or dynamics is inferred here.

## Numerical behavior and responsibility boundary

Numeric operands are converted to double before the frozen arithmetic,
including inputs whose existing validators permit integer or single types.
The eight output components are doubles. This avoids integer saturation
without rescaling or modifying inputs. Results are direct floating-point
evaluation of the formulas: no tolerance, rounding, clamping, epsilon
correction, normalization or extra output validation is introduced. A small
negative result stays negative. No special arithmetic-overflow policy is
added beyond existing input validation and double arithmetic.

Negative gaps, negative w, negative longitudinal velocity, unusual vehicle
ordering and states away from nominal lane centers remain representable.
There is no safety rejection, collision check, lane-membership check,
progressive-motion restriction or theoretical-applicability check.

This phase adds no capability evaluator, reserves, horizons, GF1/GF2/GF3,
control selection or trajectory-level theory adapter. The existing
`evaluateCapability` placeholder remains unchanged. A later layer may call
this single-state function on individual SimulationResult samples; no
production trajectory converter or P0.2.7 functionality is included here.
