## API and matching-input precondition

```matlab
c = avlc.analysis.evaluateLocalCompatibility(scenario,z,cap,diagnostics);
```

Inputs must be matching frozen current-state outputs. Scenario validation is
reused; local validation checks only consumed scalar values and logical flags.
Malformed inputs raise `AVLC:InvalidLocalCompatibilityInput`. The function does
not call the capability evaluator, diagnostics, engine or trajectory adapter.
It does not recompute capability, frontier or reserve formulas. Certification
does compute GF2-specific p/q, discriminants and branch comparisons. Inputs
are not modified; coherent provenance of all four inputs remains the caller's
responsibility, rather than a duplicate full capability validator.

status is authoritative: PRESERVABLE, NOT_PRESERVABLE, UNDEFINED.
defined is logical. On UNDEFINED, domainCase is UNSUPPORTED, reason identifies
failed checks, intersection fields and localPreservable are NaN, constraints
are empty and classification flags are false (not classifications of an
uncertified state). On a defined result, localPreservable and nonempty are
logical; domainCase is REGULAR_W_POSITIVE or PROGRESSIVE_W_ZERO.

## Certified domain and exclusions

The implementation certifies a sufficient explicit finite chart of §49:

- w>0 for the regular theorem, or w=0 for the separate §67 classification;
- finite HO,HT and all three reserves, with dualCapable and nonnegative reserves;
- pO=HO-w/A,qO=HO+w/A,pT=HT-w/A,qT=HT+w/A all strictly positive;
- positive target discriminant and positive discriminants of active finite
  rear/front opportunities, with positive corresponding closing speeds;
- supported abort/upper topology matching the supplied opportunity values
  and comparison flags; all nonlimiting abort opportunities strictly exceed HO;
- each inactive reserve strictly positive;
- auxiliary strict slack: y>0 and gR,gF,gT>0. The completion overshoot frontier
  is already represented by rT and is not incorrectly required to be strict.

This deliberately does not classify auxiliary-boundary states outside this
explicit sufficient chart. w=0 removes only the w>0 restriction: it does not
certify zero opportunities, collapsed discriminants, p/q=0 or infinite/NaN
frontiers. These remain UNDEFINED, not proved incompatible. No tolerance
alters any sign, equality, tie or certification predicate.

## Intersection, empty active set and classification

The admissible box is [-B,C] x [-A,A]. Append every active boundary set, then
take max of lower bounds and min of upper bounds in each axis. The intersection
is nonempty iff both lower<=upper comparisons hold. Contradictory bounds are
retained as an auditable empty intersection, never clamped. With no active
reserve the intersection is the whole box. There is no sampling, optimizer
dependency, selected action or witness-control output.

Within the regular certified domain:

- Type-L: rO=0,lT=0,rT>0 (lateral separation).
- Type-X: rO=0,rT=0,lT>0 with front membership and upper-I membership,
  including their inherited locking switches (longitudinal conflict).

These flags explain configurations; only intersection determines truth.
They are not exhaustive incompatibility labels. Separate current execution
capability remains unchanged even when GF2 is NOT_PRESERVABLE.

## Separate w=0 progressive requirements

Section 67 changes the base box to [-B,C] x [0,A]. Abort requirements and
upper I/switch locking sets demand ay=-A, so their intersection with this
box is empty. Lower requires (C,A). Strict upper II instead requires
[-B,C] x {0}, exactly, from pathwise invariance. All simultaneous requirements
are appended before intersection; no first-match on the active reserve set
is used. Type-L/X labels are reserved for the regular classification.

## Audited domain resolution: singleton completion window

The requested lower+upper and triple-active incompatibility examples cannot
be certified regular states. For pT,qT>0:

```text
Dplus-Dminus = A*pT*qT/2 > 0
Dplus > D0 >= Dphys
```

Thus YTin<YTout, making lT=rT=0 impossible. The real P0.2.7 singleton-window
examples have HT=w/A, pT=0. They are tested as UNDEFINED (including the
triple-active example), in accordance with the higher-priority domain rule.
They are not fabricated as valid regular states or incorrectly assigned
NOT_PRESERVABLE. The focused independent audit accepted this domain-based
resolution of the earlier test expectations in sections 22/37. The frozen
theorem is not extended: these degenerate examples remain UNDEFINED.
