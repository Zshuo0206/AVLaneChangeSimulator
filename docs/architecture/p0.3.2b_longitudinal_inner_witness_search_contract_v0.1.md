## Finite search class and options

One call fixes N and searches uniform piecewise-constant accelerations:

```text
partition: ti=i*T/N, i=0,...,N
variables: a=(a1,...,aN)'
control: ax(t)=ai on [t(i-1),ti)
bounds: -B<=ai<=C
```

The implementation uses `linspace(0,T,N+1)'` with exact endpoint values.
This finite class U_N is a subset of the admissible measurable-control class.
N is never increased automatically, and statuses need not be monotone in N.

Only two option fields are supported; unknown options are rejected:

| Option | Default | Validation |
| --- | --- | --- |
| numSegments | 8 | Finite real positive integer |
| maxCutIterations | 20 | Finite real nonnegative integer |

Omitted options or a scalar empty struct use defaults. No random start,
moment objective, lateral coordinate, terminal capability target, parallel
search or adaptive N schedule is supported. Inputs are unchanged.

Only B/C, six initial longitudinal coordinates, T and the two options are
consumed. No y,w,A,W,overshoot, Road, capability or GF2/reserve result is read.
Extra unused Scenario/state fields are ignored; full Scenario validation is
not required. Scalars must be finite real numeric and double-compatible;
B,C>0 and T>=0. Negative initial gaps are valid data, not malformed input.

## Exact fixed-time coefficients and LP formulation

For X(t)=integral_0^t (t-u)*ax(u)du, the fixed partition gives

```text
X(t)=q(t)*a
qi(t)=0                              if t<=si
qi(t)=(t-si)^2/2                     if si<t<ei
qi(t)=hi*(t-(si+ei)/2)               if t>=ei
```

Here si/ei are segment start/end and hi=ei-si. The full-segment branch is
evaluated equivalently as `hi*(t-si-hi/2)` to avoid summing large endpoints.
These coefficients are exact integral formulas, not control samples.

At every fixed cut time, add three necessary linear inequalities in order
R, RT, FO:

```text
-q(t)*a <= gR0-cR0*t
-q(t)*a <= gT0-cT0*t
 q(t)*a <= gF0-cF0*t
```

The initial cut set consists of all partition nodes, including 0 and T.
Initial LP feasibility guarantees only nodal constraints numerically; it
does not imply segment-interior or whole-prefix safety.

Use zero objective `f=zeros(N,1)`, no equalities, and the acceleration box.
The solver point is a candidate, not a best/optimal safe control, moment
support point or traffic policy.

## Dependency and solver result handling

Positive-T search requires `linprog` and `optimoptions` from MATLAB
Optimization Toolbox, plus its license. There is no fallback LP solver.
Only `optimoptions('linprog','Display','none')` is set: no legacy algorithm
or altered solver tolerance is hard-coded. This interface was checked against
the official [linprog documentation](https://www.mathworks.com/help/optim/ug/linprog.html).

Any finite scalar **positive** exitflag and finite real vector of the correct
dimension permits a verifier call; success is not limited to one particular
release's exitflag value. Every other result is UNRESOLVED. Raw exitflag and
solver output are preserved per solve and in the final search metadata.

`solverReportedSearchClassInfeasible` is only a best-effort message diagnostic:
it recognizes text such as "infeasible", "no feasible", "no point satisfies"
or "不可行". It neither maps a negative flag to global truth nor guarantees
recognition of every locale's message. Raw output is the audit source.
Unrecognized messages and any nonpositive flag still produce UNRESOLVED.

## Cutting-plane loop and exact separation

```text
build LP at current cut times
linprog -> candidate
frozen P0.3.2a verifier -> certificate
valid certificate -> WITNESS_FOUND
otherwise -> exact negative-gap minimum times -> add cuts -> next LP
```

Candidate numeric values are passed to the verifier unchanged: no clipping,
rounding, zero snapping or repair. Normalizing row/column representation in
the frozen certificate does not change their values. Its continuous-time
quadratic minima, control bounds and safety truth are never reimplemented.
The searcher does not recompute eta/zeta, terminal propagation or raw lens.

For each strictly negative global role minimum, read its time from the
certificate. At every new time add **all three** R/RT/FO inequalities. Sort
and deduplicate using exact double equality only; nearby times are not merged
using epsilon. Shared role times add one cut time.

If any negative minimum occurs at an already-present cut time, stop with
`SOLVER_CONSTRAINT_MISMATCH`. This includes a tiny negative gap at a node;
LP numerical feasibility cannot override the frozen verifier. If the
certificate rejects acceleration bounds, stop with
`SOLVER_CANDIDATE_OUT_OF_BOUNDS` and add no cuts.

`maxCutIterations` counts successful cut-set refinements after rejected
candidates. A value of zero still allows the initial LP and verification,
then returns CUT_LIMIT_REACHED if that candidate needs a new cut. At most
maxCutIterations+1 solves occur. Multiple role cuts in one refinement count
as one iteration. No automatic change to N occurs.

## Authoritative status semantics

Only two statuses exist:

- **WITNESS_FOUND**: the frozen certificate has `validWitness=true` and
  `status=SAFE_WITNESS`. Top-level witness times/ax equal its control times/ax.
  The supplied control is a certified longitudinal physical-safety witness.
- **UNRESOLVED**: this finite numerical search did not obtain a valid
  certificate. It does not prove the continuous safe-moment set empty,
  fixed-T shared preservation impossible, or tauDual<T.

Search-class LP failure, including an infeasibility report after valid cuts,
is never upgraded into continuous measurable-control infeasibility. Even an
exact exclusion of a fixed U_N would not exclude all measurable controls.
Solver numerical tolerances belong to candidate generation only. The frozen
verifier still uses gap>=0 and exact control bounds without safety tolerance.

Only WITNESS_FOUND exposes usable top-level witness/certificate. On every
UNRESOLVED outcome they are scalar empty structs, even if a failed candidate
exists. Failed candidates and their full certificates remain in attempts.

## Zero horizon and error policy

For T=0, construct `times=0,ax=[]` and call only the verifier; no linprog or
optimoptions invocation occurs. Valid initial gaps give WITNESS_FOUND;
unsafe gaps give UNRESOLVED / INITIAL_STATE_UNSAFE. This path works without
Optimization Toolbox. Solver availability may be inspected for metadata.

Malformed consumed fields/options, T<0, or invalid B/C raise
`AVLC:InvalidLongitudinalWitnessSearchInput`. Solver availability, numerical
failure and physical failure are not malformed-input errors.

| UNRESOLVED reason | Meaning |
| --- | --- |
| SOLVER_UNAVAILABLE | Solver/options function or license unavailable |
| SOLVER_FAILURE | Solver/options threw a numerical/runtime exception |
| SOLVER_NO_USABLE_CANDIDATE | No positive-success, finite correctly sized point |
| SOLVER_CANDIDATE_OUT_OF_BOUNDS | Unmodified point rejected by exact control bounds |
| SOLVER_CONSTRAINT_MISMATCH | Negative certified gap at an existing cut |
| CUT_LIMIT_REACHED | Refinement budget exhausted |
| VERIFIER_ARITHMETIC_FAILURE | Frozen verifier raised its arithmetic-failure ID |
| SEARCH_ARITHMETIC_FAILURE | Derived LP coefficients/right-hand sides nonfinite |
| PARTITION_NOT_REPRESENTABLE | Uniform nodes cannot be strictly increasing in double |
| INITIAL_STATE_UNSAFE | T=0 certificate failed |

Verifier arithmetic failure is not labeled unsafe and supplies no cuts.
Its exception ID/message are preserved. Other unexpected verifier exceptions
are surfaced rather than silently reinterpreted. Solver exceptions also
preserve diagnostics; undefined-function/license errors mark unavailability.

## Output and trace schema

```text
result
  status,witnessFound,reason
  witness: times,ax                  (empty struct unless found)
  certificate                       (empty struct unless found)
  search:
    numSegments,maxCutIterations,solverAvailable,partitionTimes,cutTimes
    solveCount,verifiedCandidateCount,cutIterationCount
    solverReportedSearchClassInfeasible,finalExitflag,finalSolverOutput
    exceptionIdentifier,exceptionMessage
  attempts (column struct array):
    index,source,exitflag,solverOutput,ax,verifierCalled
    certificateStatus,validWitness,minimumR,minimumF,minimumT
    violationTimes,newCutTimes,certificate,exceptionIdentifier,exceptionMessage
```

Numeric partition/cut vectors are columns. `solveCount` counts actual solver
invocations, including thrown calls. `verifiedCandidateCount` counts completed
verifier returns; a thrown arithmetic audit is recorded by verifierCalled but
does not increment that count. `cutIterationCount` counts applied refinements.
`newCutTimes` records cuts actually added, not merely proposed beyond a limit.

The T=0 verifier call has one attempt with source ZERO_HORIZON and NaN
exitflag, zero solves, and one completed verification on a normal return.
Ordinary solver attempts use source LINPROG. Without a verifier return,
certificateStatus is empty, minimum fields NaN and certificate empty; no
certificate is fabricated. Last failed full certificates are stored in trace.

## Critical false-positive regressions and observed probes

For B=C=2,T=2,N=1, take R gap=0.5, closing rate=2, other gaps=100 and
rates=0. Nodal constraints allow a in [1.75,2], but the interior minimum is
`0.5-2/a<0` at `2/a`. The FO counterpart uses a in [-2,-1.75], with the same
interior violation magnitude and opposite acceleration sign.

On MATLAB R2024b / Optimization Toolbox 24.2, direct public-API probes gave:

| Probe | First candidate | Certificate | New cut time | Solves/refinements | Final status |
| --- | --- | --- | --- | --- | --- |
| Rear interior collision | a=1.75 | UNSAFE_WITNESS, minR=-9/14 | 8/7 | 2/1 | UNRESOLVED |
| Front interior collision | a=-1.75 | UNSAFE_WITNESS, minF=-9/14 | 8/7 | 2/1 | UNRESOLVED |

Both first candidates satisfy endpoint gaps (0.5 at 0, zero at 2), yet fail
inside. The next LP reports no point; this remains only a numerical finite
search-class diagnostic. No WITNESS_FOUND is returned.

For the easy scene with all initial gaps=100 and closing rates=0, all bounded
controls over T=2 have gaps at least 96. Observed N=1,2,8 candidates were
constant a=-2. Each independently reverified certificate had minima
`(R,F,T)=(96,100,96)` and moments `(eta,zeta)=(0,0)`. This point is not claimed
optimal; a different solver release may propose a different valid point.
